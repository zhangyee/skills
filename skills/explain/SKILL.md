# Explain

让读者理解问题的答案、具体机制和适用边界。根据问题选择调查方法，再用自然中文解释。正文用中文，代码符号、路径、命令和标准名称保留原样。这是清晰表达规范，不声称符合 ASD-STE100。

## 选择任务

从当前问题和对话判断对象、用途与读者背景。范围不明确但能合理判断时，简短说明采用的理解并继续；只有不同理解会实质改变答案时才澄清。

按下表读取需要的参考文件；不为完整而加载全部文件。这些是可组合的调查视角，不是要求用户记住的子命令，也不是回答的固定标题。

| 问题 | 方法 |
|---|---|
| 概念是什么、把给定文本讲清楚 | 用当前材料直接解释；不默认调查仓库 |
| 组件负责什么、谁创建或使用它 | 读 [trace.md](references/trace.md) 的组件部分 |
| 一次操作怎样执行、何时返回 | 读 [trace.md](references/trace.md) 的执行部分 |
| 数据从哪来、如何转换、在哪里校验 | 读 [trace.md](references/trace.md) 的数据部分 |
| 状态如何变化、取消或结束后怎样 | 读 [trace.md](references/trace.md) 的状态部分 |
| 模块如何分工、依赖和边界在哪里 | 读 [architecture.md](references/architecture.md) 的结构部分 |
| 当初为何选择这个实现或数值 | 读 [rationale.md](references/rationale.md) |
| 当前方案是否合适、与替代方案如何比较 | 读 [architecture.md](references/architecture.md) 的取舍部分 |
| 变更改了什么、影响哪里 | 读 [change-and-behavior.md](references/change-and-behavior.md) 的变更部分 |
| 为什么出现某个现象或结果差异 | 读 [change-and-behavior.md](references/change-and-behavior.md) 的现象部分 |

“为什么”可能是在问运行机制、历史动机或当前评价，先辨别再调查。例如，重复请求追流程和状态，选择轮询的历史原因查记录，现在是否改推送则比较当前需求。只补充会影响答案的其他视角。

## 证据与范围

- 从相关文件、符号、输入或操作开始，阅读实际实现。目录名、注释和类型声明是线索，关键行为要核对实际接入与执行位置。
- 用关键文件、符号和已核对的行号支持实现结论；外部事实使用对应来源。只报告实际读过、查过或运行过的内容。
- 分清材料明确支持的事实、推断和未知。代码行为不能证明作者意图，静态分析不能冒充实测，搜索未发现不能证明不存在。
- 从具体问题逐步扩大范围；核对边界契约足以回答时，不继续追完其内部。只有独立且复杂的调查确有收益、环境和授权允许时才委派，不固定代理数量或模型。
- 解释已经连接问题、机制与结果，并覆盖会改变结论的条件时结束。证据不足时说明具体缺口，不以猜测补齐。
- 用户只要求解释时，交付解释。用户同时授权修改或验证时，完成已授权工作；本技能不新增审批或擅自扩大任务。

## 讲清楚

- 先直接回答，再给理解答案所需的背景和机制。当前请求要求完整分析时一次覆盖，不为等待追问而截断必要内容。
- 写清谁在什么条件下做什么，得到什么结果。沿具体操作、输入或例子展开，使因果、顺序、转折和例外有明确连接。
- 解释当前读者需要的陌生术语。可以就地定义，也可以先讲机制再给名称；用熟悉的词解释新词。同一概念保持同一名称。
- 按意思组织句子与段落，不设字数、句数上限。读者需要回看才能确定主语、条件或关系时，拆句或重排；条件与结果放在一起更清楚时保留完整句子。
- 示例与比喻用于帮助理解，并说明会影响结论的差异；假设例子明确写成假设，不补成当前系统的事实。
- 保留数字、单位、条件、例外、限制和证据强弱。不为通俗新增消息数量、执行顺序、性能结果或业务保证。
- 标题、列表、表格、代码片段随问题选择。组织结构服务阅读，不套固定报告模板，不把函数清单当成机制解释。

## 按需画图

先确定读者看图要弄清的关系。图比文字更容易呈现该关系时用 Mermaid；简单概念、选项比较或短步骤可直接用文字、表格或列表。

- 职责、依赖、数据处理与分支可用 `flowchart`；调用先后、返回、等待与并发可用 `sequenceDiagram`；事件和条件引起的状态变化可用 `stateDiagram-v2`。实体关系才考虑 `erDiagram`，其他图型按实际需要和环境支持选择。
- 节点、箭头、方向、条件和顺序均应对应材料。调用、数据流和依赖的含义要清楚；推测关系显式注明，不只靠虚线区分。
- 图聚焦当前疑问，标签简短且准确。只有拆分更清楚时才拆，不设图数或节点数指标。图前给必要语境，图后补原因、限制与例外，不逐条复述。
- 图示不能替代关键条件的文字说明。有适用渲染工具时检查语法和效果；未经实际检查，不声称已验证，也不编造通用渲染限制。

## 交付前检查

读者能否直接找到答案，沿主体、条件和因果理解结果，并辨认结论的适用范围？关键断言是否有材料支持？是否添加了原文没有的机制，或把“可能”写成了“确定”？删除重复内容，但保留所有会改变判断的信息。

### 事实保留示例

原文：“该系统通过异步消息，将订单创建与库存、支付处理分开，采用 Saga 编排。”

解释：“订单创建通过异步消息与库存、支付处理分开协调。发送消息的一方不必等待接收方完成处理。Saga 是协调多个步骤及其失败处理的一种方式。原文没有交代消息数量、库存与支付的执行顺序，也没有说明具体如何补偿失败。”
